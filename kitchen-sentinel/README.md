# 灶安 Kitchen Sentinel

家庭厨房燃气与火灾安全监测平台的本地全栈原型。项目包含浏览器端、Python 服务、MySQL 数据库、STM32 实物采集和独立设备模拟器。STM32 已通过 SWD 调试器把真实原始采样送入本地后端与看板。

## 当前范围（v1.1.0，2026-10-15）

- React + TypeScript 浏览器工作台：监控总览、设备、报警、联动控制、历史数据、系统测试、系统设置和审计。
- FastAPI + SQLAlchemy 后端：认证、权限、设备上报、报警生命周期、幂等控制命令、CSV 导出和可选模型摘要。
- MySQL 8：设备、采样、报警、命令、规则版本、会话和审计日志。
- 独立设备模拟器：正常、燃气升高、火灾、瞬时尖峰、传感器故障、上报中断和命令超时场景。
- STM32F103C8T6：四路 ADC、两路数字输入、测试联动输出；`stm32-001` 使用独立硬件身份，SWD 实物数据与 `kitchen-001` 模拟数据分开保存。
- 自动响应、报警确认和人工处置分别记录：能力内先自动保护，火灾、超限、失败或超时升级人工；现场执行器异常也可填写说明转人工。

燃气和烟雾字段在当前版本是 0–100 的相对指标，不是经过标定的 ppm 或 %LEL。模拟器回执不代表真实阀门物理状态。

## 本机启动

默认使用项目虚拟环境执行 `python start.py`（等同于 `--hardware`），启动后访问 `http://127.0.0.1:8000`。该模式统一管理后端和 SWD 采集，退出按钮或 Ctrl+C 会停止本次启动的进程。已有数据库可加 `--skip-bootstrap`；不需要自动打开浏览器可加 `--no-browser`。

ATK-CMSIS-DAP 需保持连接；采集运行期间不能同时打开其他 SWD 调试或烧录工具。重新烧录前先退出硬件采集。详细入口及证据见 `docs/STM32实物数据接入与注释日期说明.md`。模拟场景在网页“系统测试”中独立启动，不改变正式硬件监测。

1. 确认 MySQL 8 服务运行，在 `.env` 填写 `DB_USER` 和 `DB_PASSWORD`。该文件已加入忽略规则，不要提交或分享。
2. 在项目目录执行 `python start.py`。这是系统总入口：它会自动使用项目 `.venv`，创建数据库、执行迁移、启动 API、浏览器端和 STM32 实物采集，并打开 `http://127.0.0.1:8000`。
3. 按 `Ctrl+C` 会同时停止后端和设备模拟器。初始化账号和密码在 `.runtime\access.txt`，只在本机查看。

工作台和登录页都提供“退出系统”按钮，也支持 `Ctrl+Shift+Q`。它只允许本机浏览器调用，后端会先完成应用生命周期关闭，再由总入口回收模拟器；不会删除数据库、清空缓存或写入业务表。若浏览器未打开，可直接在启动窗口按 `Ctrl+C`。

总入口支持以下参数：`python start.py --simulation` 显式选择模拟器模式；`python start.py --no-simulator` 只启动网页和 API；`python start.py --skip-bootstrap` 跳过已完成的数据库初始化；`python start.py --no-browser` 启动后不自动打开浏览器；`python start.py --port 8010` 使用其他端口。入口会在启动前检查前端构建、`.env` 和端口，并在自定义端口时自动更新本地 CORS/WebSocket 来源。

同一目录启用跨进程独占锁，重复双击会复用已经启动的访问地址，不会再创建另一个版本的后端。总入口只回收本次创建的后端和设备进程。Windows 使用进程作业对象管理进程树，在受限的 IDE 环境中会自动退回当前进程组清理，不会按名称结束用户正在运行的其他 Python 程序。

后端使用异步维护任务和线程池隔离数据库操作，WebSocket 快照不会阻塞事件循环；MySQL 连接池默认保留 10 条连接、允许临时扩展 20 条，维护任务按批次处理过期会话与命令，避免数据量增加后单次事务无限变大。

默认访问地址为 `http://127.0.0.1:8000`。首选端口被占用或受系统限制时，总入口会从该端口起尝试最多 20 个端口，打印并打开最终可用的地址。请以启动日志中的“系统已启动”地址为准；模拟器和登录来源白名单会同步使用选定端口。监听地址错误不会通过切换端口掩盖，而会显示具体系统错误。

如果需要单独调试，仍可使用 `python scripts\bootstrap.py`、`python scripts\run_backend.py` 和 `python scripts\run_simulator.py`。这些脚本同样会自动切换到项目虚拟环境，不会再误用系统 Python。

如果当前终端位于工作区上级目录，也可以直接使用绝对路径启动总入口：

```powershell
& "E:\生产实习 260906-261016\kitchen-sentinel\.venv\Scripts\python.exe" "E:\生产实习 260906-261016\kitchen-sentinel\start.py"
```

总入口及三个单独脚本都会根据自身文件位置定位项目根目录，因此不会依赖终端当前所在目录。

### PyCharm 项目设置

如果从上级目录 `E:\生产实习 260906-261016` 打开项目，IDE 配置已将 `kitchen-sentinel` 标记为 Python 源目录，因此 `from backend.core...` 会从正确位置解析。若 IDE 仍显示旧的“非项目文件”提示，执行一次 **文件 → 重新加载磁盘中的所有文件**，或关闭项目后重新打开，让它重读 `.idea` 配置。

项目依赖安装在 `kitchen-sentinel\.venv`，请将 PyCharm 的项目解释器设为 `E:\生产实习 260906-261016\kitchen-sentinel\.venv\Scripts\python.exe`。当前工作区的旧配置显示 Python 3.14，它不是本项目的虚拟环境解释器；若仍用它，IDE 可能继续提示找不到 FastAPI 等第三方包。

前端已经构建到 `frontend/dist`，后端检测到该目录后会直接提供静态页面。开发时可在 `frontend` 目录执行 `pnpm dev`，它会把 `/api` 转发到本地后端。

## 使用与测试

正式页面只显示现场设备及其报警，监测和报警自动刷新。所有异常恢复后继续留档，确认、恢复与人工处置分别保存；命令失败和超时同样生成待确认事件。页面提示音和桌面通知可点击开启，浏览器关闭后的外部推送尚未接入。

系统测试页集中提供模拟器启停、场景、测试报警及测试控制，另有硬件原始采样、固件自检及三秒执行器分项测试。实物命令必须有实际固件能力和回执，火灾禁止普通风扇与消音，险情优先中止测试。

已清理旧的 8001 实例；当前入口为 8000。若打开旧地址，请改用当前启动地址，不要并行运行另一个旧版后端。

## 代码约定

- 报警规则位于 `backend/domain/rules.py`，是无数据库、无网络的纯函数，便于边缘端和服务端共同验证。
- `backend/services/monitoring.py` 只负责业务编排，数据库模型和 HTTP 路由保持分离。
- 写接口需要角色权限和 CSRF 令牌；设备接口使用设备 Bearer 令牌。
- 关键状态都写入数据库：报警的触发、恢复、确认和备注；命令的入队、下发、回执和超时。
- 注释解释业务原因和边界，不重复描述语法。
- 所有新增、修改和重构执行 `AGENTS.md`：文件头用中文说明职责、功能、技术栈和关联模块，主要函数、组件与关键逻辑就近说明；详细示例和入口见 `docs/代码注释规范与模块索引.md`。
- 本次硬件接入改动的注释使用《实习日志 全六周.xlsx》对应的具体日期，并说明功能；不标实际编写时刻或工具身份。第三方原始版权、作者和版本说明保留。
