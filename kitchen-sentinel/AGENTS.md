# 中文代码注释约定

本项目后续的新增、修改和重构均须执行本约定，适用于后端、前端、网关、模拟器、启动脚本、数据库迁移、测试及 STM32 工程自编代码。

1. 每个源文件开头使用中文介绍文件职责、已经实现的主要功能、实际采用的技术栈和关联模块。阅读文件头应能辨别该文件在系统中的位置、输入来源和输出去向。
2. 主要函数、方法、组件、类型及重要事件处理函数均须中文说明。说明用途、重要输入输出、调用关系，以及会影响理解的状态变化或异常边界。Python 使用文档字符串，TypeScript 使用函数或组件前的中文注释，C 使用函数或接口前的中文块注释。
3. 关键逻辑就近说明原因，包括采集与滤波、状态机、报警恢复、人工确认、保护输出、认证授权、持久化、幂等、断线重连、资源清理。不要逐行翻译语法，不使用空泛的套话。
4. 日期标为“编写/修改日期（日志对应）：YYYY-MM-DD”，依据《实习日志 全六周.xlsx》对应工作项安排。功能后来修正时补充相应日期及修改用途。该日期表示与日志的对应关系，不能用来替代实际测试、烧录、回执或验收时间。
5. 日期依据及数据链路说明见 `docs/STM32实物数据接入与注释日期说明.md`。功能归属跨日期时，可在文件头列明多个日期，并在函数旁写明具体对应项。
6. 注释不添加生成工具署名，不写尚未实现的功能，不把模拟器回执、控制寄存器或 PWM 指令称为已经验证的物理动作。自动处置、信号恢复、报警确认及人工处置保持独立说明。
7. 原厂 SDK、第三方依赖和参考资料保留版权、作者及原始版本信息。项目入口或本项目改动处补充中文说明，不批量重写依赖源码。严格 JSON 等不支持注释的配置文件通过邻近说明文档解释，避免破坏格式。
8. 注释修改后检查语法和相应构建。仅补注释时应核对可执行代码未改变，不重复烧录固件或操作执行器来证明注释已生效。
