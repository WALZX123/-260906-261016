# 自动响应、报警确认与人工处置

当前版本：PC v1.1.0／STM32 状态版本 4，核对日期 2026-10-15。

## 处理原则

系统保留自动响应。能力范围内的异常先自动保护并观察效果；火灾、超过设置范围、保护命令失败或响应超时才升级人工处置。报警确认只是记录人员已知悉，不会停止自动保护、解除持续异常或重新开阀。

| 情况 | 自动响应 | PC 状态 | 人工要求 |
| --- | --- | --- | --- |
| 燃气测试指标越限且在自动处置范围内 | 低压模型关阀、排风、蜂鸣器和保护输出，观察效果 | 等待输出反馈 / 自动输出已反馈、观察效果 | 保留报警待确认；不强制人工处置 |
| 自动响应后测试信号恢复 | 模拟阀保持关闭 | 信号已恢复 + 报警待确认；模拟器完整闭环可标记自动处置完成（模拟） | 确认报警记录；实物效果另行核验 |
| 火焰或火灾警情 | 自动保护继续执行，普通测试风扇关闭 | 保护输出已反馈 + 需人工处置 + 报警待确认 | 立即人工处置；确认报警不等于完成处置 |
| 燃气达到人工介入阈值 | 自动保护继续执行 | 超过自动处置范围，需人工处置 | 人工处理并记录 |
| 保护命令失败或信号持续超过观察时限 | 保留已经执行的保护 | 执行失败 / 响应超时，需人工处置 | 人工检查故障或危险原因 |
| 短时掉线后恢复 | 独立重试采集连接，保持 PC 和报警服务 | 等待自动重连 / 连接已恢复 | 恢复前超时则升级人工；否则只保留报警确认 |
| 传感器无效、待标定或连接异常超时 | 不把无效数据当正常，不撤销已有保护 | 需人工检查 | 核查接线、量程、标定与设备连接 |

当前平台默认燃气报警阈值为相对指标 40，人工介入阈值为 80，自动响应观察时限为 30 秒。后两项可在系统设置修改。它们不是 ppm/%LEL 安全限值。固件上电默认阈值为燃气 40、烟雾 45、温度估算 60°C；连接后同步平台三项阈值，并上报实际应用的版本和值。本轮平台燃气阈值为 60、版本为 4，已核验固件同步。平台的持续、恢复与人工升级时限仍单独管理。

## 事件生命周期

每条报警分别保存触发条件状态、自动响应进度、确认人/确认时间、人工升级原因和现场处置记录。自动信号恢复不会删除待确认记录；点击“确认收到报警”不会改变设备输出。需要人工处置的事件只有在触发条件恢复、报警已经确认、并填写现场核查说明后，才能记录处置完成。该接口不下发开阀命令。

燃气、火灾、采样异常和设备离线事件均保留记录，自动处置完成的事件也不自动确认。恢复日志明确保留待确认状态；同类异常再次发生时创建另一条事件，不能覆盖上次记录。人工确认保存确认人、日期时间与处理说明。列表优先显示活动、待处置和待确认事件；统计覆盖全部历史，较早记录可继续按游标加载，不会因为移出首页而删除。命令失败和超时也独立生成控制执行异常，后续重试成功只标恢复，不代人工确认。

现场发现执行器未动作时，可填写说明并使用“报告现场异常并转人工”。这不会确认报警或更改设备输出，而是保留现场异常原因，要求人工核查。没有阀位传感器时，系统无法仅从 PWM 比较值自动识别舵机卡住、断电或接线问题。

PC 首页增加“自动响应与人工核查”，报警中心同时展示三类状态，并支持“报警待确认”和“需人工处置”分别筛选。历史未保存动作回执的事件显示“历史动作未记录”，不补造成功结果。

自动动作反馈目前来自 SWD 读取的控制寄存器；它不能代替实际阀位、继电器触点、电源断开或灭火效果确认。实物数据尚未完成标定，因此信号回落仍标记为测试信号恢复；模拟器的闭环成功则明确带“模拟”字样。

## 固件保护修正

`Users/response_policy.c/.h` 统一处理自动输出：火灾优先抑制风扇，危险触发后保持模拟阀门关闭，信号回落只解除当前蜂鸣器/继电器测试输出。当前无可燃气体的低压模型启用燃气排风联动，火灾时始终禁止普通风扇。实际可燃气体环境不能照搬普通模型风扇策略。

阀门锁定只在本次 MCU 运行期间保留，掉电或复位后不保留，本原型没有实现合格燃气切断阀或自动灭火装置，不用于真实燃气与市电保护。PC 人工确认不会复位该锁定。

状态块版本 4 报告危险类型、阀门锁定、风扇配置、执行能力、命令结果、限时动作余量和实际规则版本；控制信箱采用版本 2。网关按实际状态区分燃气、火灾、复合报警，不再把所有报警都写成火灾。采集有效与是否标定分开：火焰/本地危险信号不会因其他通道待标定而被平台屏蔽。

## 设计依据

国家消防救援局的厨房火灾提示明确要求关闭普通抽油烟机/排风机；燃气泄漏提示也指出不应情急打开普通排气扇。项目因此保留自动保护，但不把普通风扇视为灭火装置或真实燃气现场的通用处置设备。
