## 已完成测试

1. Windows 枚举出 `COM3`，注册表将其标识为 ATK-DAP 的 USB Serial Device。
2. pyOCD 识别 ATK-CMSIS-DAP，并通过 SWD 读取 DAP IDCODE `0x1ba01477`。
3. 读取 STM32 设备 ID `0x410`、Flash 容量 64 KB 和唯一 ID，确认调试链路连接到了真实 STM32F103C8 器件。
4. 读取当前 Flash 起始向量：`0x200048b0 0x08000275 0x08002fd1 0x08002f97`，说明板上已有可启动固件。
5. 暂停内核后向 SRAM `0x20000000` 写入 `0x1234abcd` 并读回相同值，确认调试器的 halt、内存写入和读取路径工作；随后已复位内核。
6. 串口 `COM3` 以 115200/8N1 只读监听 8 秒，未收到启动文本；当前固件是否输出串口日志仍需在固件协议中确认。
7. MB002 热敏参考工程和 MB026 TCP 透传参考工程均由 Keil 命令行编译成功，均为 0 Error / 0 Warning；MB026 工程生成了 HEX 文件。

## 2026-10-13 的烧录问题（2026-10-14 已解决）

使用 pyOCD 加载 MB026 HEX 时，调试器能够连接并停机，但在 `Erasing...` 阶段无响应。已停止该次操作，重新读取 Flash 起始向量仍为原值，确认本次没有完成擦除或写入。原因更可能是 ATK-DAP 的专用烧录路径与通用 pyOCD Flash 算法不兼容；不能据此声称固件已经烧录。

2026-10-14 核对 ATK-MB000 手册后修正：资料包里的 `ATK-BDAP.exe` 用于升级仿真器自身固件，并非 STM32 目标程序下载工具。本次未升级仿真器固件，使用 pyOCD 通信兼容选项解决了下载问题，见下方实机记录。

## 本机复现入口

以下命令只做调试器识别和只读信息检查：

```powershell
Set-Location 'E:\生产实习 260906-261016\kitchen-sentinel'
& '.\.venv\Scripts\pyocd.exe' list -p -v
& '.\.venv\Scripts\pyocd.exe' commander `
  --pack '.runtime\hardware-test\Keil.STM32F1xx_DFP.2.3.0.pack' `
  -t STM32F103C8 -u ATK-20240820 -M attach `
  -c 'read32 0xE0042000 4' `
  -c 'read32 0x1FFFF7E0 4' `
  -c 'read32 0x08000000 16' `
  -c 'exit'
```

编译产物位于 `.runtime\hardware-test\mb026-tcp.hex`。该文件暂时只作为待下载测试固件保存，不能把它当作已经运行在板上的固件。

## 下一轮硬件测试顺序

1. 用 ATK-BDAP 或匹配的 Keil 下载驱动下载一个只包含串口心跳、LED 和安全低电平初始化的测试固件。
2. 复位后监听 `COM3`，确认启动版本、芯片时钟和串口收发。
3. 断开高功率负载，仅接 3.3 V 传感器模块，依次测试 ADC 原始值：电位器、热敏、火焰；烟雾模块先确认分压后的电压范围。
4. 在不接市电的前提下测试 OLED、蜂鸣器、继电器低压负载、风扇和舵机 PWM；每项测试都记录默认电平和复位后的安全状态。
5. 最后再接入 MB026 TCP 透传和电脑端网关，把硬件数据标记为 `source=hardware`，并用真实设备回执替换模拟器回执。

燃气字段仍按 0–100 相对指标处理，不能把电位器或烟雾模块读数写成 ppm/%LEL；继电器只用于低压模拟负载，不能接 220 V。
