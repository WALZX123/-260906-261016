一、项目定位和目前完成情况

项目面向家庭厨房燃气与火灾监测场景，建设一个可以观察现场数据、识别异常、追踪保护动作并保存处理记录的平台。

当前已实现的交付形态是：本地浏览器工作台 + Python后端 + MySQL数据库 + 独立设备模拟器。用户从电脑浏览器使用系统，前端不需要安装独立桌面客户端。系统采用模块化单体架构，前后端代码分离，部署时由同一个FastAPI服务提供网页与接口。

目前能够演示的完整流程为：
设备模拟器生成数据 → 接口鉴权和数据校验 → MySQL保存遥测 → 服务端复核报警规则 → 更新报警记录 → WebSocket推送页面 → 模拟边缘控制器执行保护动作 → 平台展示状态 → 人工确认、备注、控制命令、历史查询与审计。

“完整流程”表示当前本地软件与模拟设备之间已经形成可演示的闭环，不表示真实硬件、手机端或云部署已经完成。

已完成范围：
1. 电脑浏览器端7个业务页面及登录页面。
2. 账号会话、角色权限、设备鉴权和请求校验。
3. 数据采集协议、遥测存储、重复数据处理与迟到数据保护。
4. 燃气、火灾、传感器故障及设备离线报警。
5. 模拟保护联动、人工控制命令及设备回执。
6. 历史曲线、采样明细、CSV导出。
7. 规则配置、用户创建、操作审计。
8. 本地规则摘要与可选外部模型分析接口。
9. 总入口启动、资源和端口检查、健康检查、进程回收、前端安全退出。
10. 基础自动化测试、静态代码检查及前端类型和构建检查。

尚未完成范围：
1. 真实传感器、控制板及执行器接入和实物标定。
2. 专门的手机应用及手机业务验收。
3. 云服务器部署、HTTPS、远程运维与集中监控。
4. 大规模设备并发验证、性能压测和长期稳定性测试。
5. 企业生产环境需要的完整备份恢复、告警通知、设备生命周期管理和发布流水线。

二、电脑端全部功能及使用方式

（一）登录与账号权限

功能：输入用户名、密码登录；刷新页面恢复会话；退出登录；按角色控制页面操作；管理员创建平台账号。

角色分为：
1. 观察员 viewer：查看监测、设备状态、报警和历史数据，允许历史导出；不能处理报警、发送命令或修改规则。
2. 操作员 operator：拥有监测查询能力，可以确认报警、追加备注、发送控制命令、选择演示场景及生成事件分析。
3. 管理员 admin：拥有全部业务权限，并可以管理规则、创建账号、查看用户列表和操作审计。

实现：登录成功后生成随机会话令牌，以HttpOnly Cookie交给浏览器；数据库保存令牌的SHA-256摘要、用户关联、CSRF令牌和8小时到期时间。前端通过 /auth/me 恢复当前用户。后端依赖函数再次检查权限，因此禁用按钮只是界面提示，接口本身也有权限限制。

密码采用随机盐和PBKDF2-HMAC-SHA256派生，迭代次数为600000。users表保存密码摘要，不保存明文密码。初始化凭据会写入本机 .runtime/access.txt；本地 .env 中也存在初始化配置，因此这两个本地文件不能作为公开材料分享。

登录接口按来源地址限制一分钟内最多10次尝试，并校验配置中的允许来源。这个限流是进程内的轻量保护，尚不是分布式限流系统。

当前账号管理支持创建和列表查看，尚无完整的改密、找回密码、账号停用和删除界面。

（二）监控总览

功能：
1. 展示燃气相对指标、烟雾相对指标、环境温度和火焰信号。
2. 展示阈值与持续触发时间。
3. 绘制燃气、烟雾、温度实时趋势，保留最近90条数据。
4. 展示设备在线状态、最近上报时间和模拟器本地报警状态。
5. 展示近期报警及人工确认状态。
6. 展示模拟阀门、风扇、模拟电源和蜂鸣器的反馈状态。
7. 区分实时连接正常、正在重连、设备离线和采样异常。

实现：前端useMonitor模块管理订阅，后端通过 /api/v1/live WebSocket约每2秒推送一次聚合快照。连接关闭后约3秒重连，前端同时保留每10秒REST快照查询作为兜底。曲线通过Recharts绘制。

设备离线时保留最后一次读数，同时标明离线，避免把旧数据误当作当前实时状态。当前总览主卡片与实时曲线默认围绕第一个设备展示，并非已经完成多设备监控大屏。

燃气和烟雾使用0—100相对演示指标；温度使用摄氏度。当前不能把相对指标解释为ppm、%LEL或真实检测仪校准结果。

（三）设备管理

功能：显示已配置节点的设备编号、名称、位置、固件标识、在线状态、最近心跳、当前演示场景、传感器通道和系统接入流程。

当前初始化设备为 kitchen-001，来源为 simulated。设备通过独立Bearer令牌鉴权，数据库只保存令牌摘要，网页不显示设备令牌。

实现：devices表保存设备档案、最近采样JSON、执行机构JSON、规则计算状态、场景版本和最后上报时间；设备页面读取聚合快照展示节点。

目前该页面主要提供设备状态和接入信息查看，不具备完整的新增设备、删除设备、编辑档案、令牌轮换和固件升级功能。模型已经支持按device_id区分设备，但完整多设备运行和界面交互仍需扩展与验证。

（四）报警中心

支持报警类型：燃气异常、火灾异常、传感器故障、设备离线。

功能：
1. 按全部、触发中、待确认、已恢复筛选事件。
2. 查看事件编号、设备、触发原因、触发时间和恢复时间。
3. 查看报警时间线。
4. 填写处理说明，记录“已知悉”的人工确认。
5. 追加处理备注。
6. 加载更早的报警记录。
7. 生成本地规则摘要，或者在配置模型服务后调用模型分析。

实现：alarms表记录报警类型、等级、状态、时间、确认人、时间线、触发证据和分析结果。同一设备同一类型已有活动报警时不重复创建事件；条件满足恢复要求后将其变为recovered。

“恢复”与“人工确认”分别保存：恢复表示自动触发条件消失；确认表示操作员已知悉。确认不会直接取消仍然存在的危险条件，也不会自动开阀。

报警证据保存触发采样、当时规则版本及数据来源，便于解释报警发生的依据。当前列表与总览统计主要基于最近100条事件，较早记录通过分页加载，不能把总览数字直接当作全库统计。

（五）联动控制

人工控制支持：
1. 紧急关阀：弹出确认框后创建关阀命令。
2. 暂时消音：模拟蜂鸣器消音15秒，报警和其他保护动作继续保留。
3. 设备自检：验证模拟采集与控制链路，尚不能代替实物硬件自检。

自动保护位于模拟边缘控制器：
1. 燃气或火灾报警时关闭模拟阀门。
2. 只有燃气报警且没有火灾报警时，将模拟风扇设为开启。
3. 火灾报警时关闭模拟电源。
4. 报警存在且没有处于消音时间内时开启模拟蜂鸣器。
5. 危险条件恢复后不自动重新开启阀门或电源。

这些动作是当前仿真程序行为，真实执行器的控制策略需要在实物接入后结合硬件规格重新验证。

命令状态：pending（等待下发）→ dispatched（已下发）→ succeeded/failed（执行结果），超出有效期则变为timeout。

实现：平台先向commands表写入命令，模拟器轮询控制接口获得待执行命令，执行后再提交回执。平台明确区分“已创建命令”和“设备执行成功”。设备每次最多获取100条有效命令，页面展示最近50条执行记录。

命令携带幂等键，服务端结合设备行锁和唯一约束防止同一业务请求重复创建；模拟器先记录已执行命令再发送回执，重试时可以复用执行记录。迟到的成功回执不能覆盖已超时状态。

当前系统不提供远程开阀功能；模拟回执也不代表真实阀位反馈。

（六）历史数据

功能：选择设备与开始、结束时间；查看趋势曲线；查看采样明细；导出CSV。

当前上限：
1. 页面查询最多1000条。
2. 页面明细展示本次查询最新100条。
3. 后端历史接口允许最多5000条。
4. CSV导出最多5000条。

实现：telemetry表保存采样时间sampled_at和服务器接收时间received_at，查询按设备和received_at时间范围筛选，结果供前端显示sampled_at趋势。时间参数要求带时区，统一转换成UTC查询；浏览器按本地时间显示。

数据库设置设备与接收时间联合索引，减少历史查询无条件扫描。CSV通过Python csv模块生成并添加UTF-8 BOM，便于常见表格软件识别中文。

当前导出是有上限的内存生成方式，不是海量数据流式导出；暂未实现游标式全量历史读取、冷热分层和数据归档。

（七）系统设置

管理员可维护8个参数：燃气阈值、烟雾阈值、温度阈值、持续触发时间、恢复确认时间、恢复回差、离线时限、命令超时时限。

默认演示值：
燃气阈值40；烟雾阈值45；温度阈值60℃；持续触发3秒；恢复确认5秒；回差5；设备离线12秒；命令超时15秒。

实现：RuleInput校验字段范围，rule_configs保存当前配置和revision版本号。修改时先锁定配置行，再比对用户提交的版本；发现其他人已经修改时返回冲突提示，避免旧页面覆盖新规则。修改前后数据写入审计日志。

模拟器通过轮询控制接口获得最新规则，随后按同一套规则执行本地计算。页面另提供部署信息、数据库连接状态、协议版本、模型配置状态和硬件接入状态。

（八）操作审计

功能：管理员查看关键操作的时间、执行者、操作类型、关联对象及详情，支持手动刷新，页面读取最近200条。

已记录事件包括：登录、账号创建、规则修改、演示场景切换、报警触发、人工确认、追加备注、事件分析、控制命令创建、设备回执、命令超时。

实现：audit_logs表以追加记录方式保存，业务操作与审计通常处于同一数据库事务中。它可用于追溯关键操作，但尚未实现防篡改签名、独立审计存储和完整合规审计平台。

（九）演示场景与使用说明

七种场景：
1. 正常监测：稳定基线采样。
2. 燃气持续升高：验证持续超限、报警和模拟关阀。
3. 火灾信号：烟雾和温度上升，随后出现火焰，观察模拟保护动作。
4. 短时尖峰：验证短暂高值不会立即触发燃气报警。
5. 传感器故障：产生无效采样，验证数据质量与故障报警。
6. 上报中断：约25秒暂停遥测并跳过命令执行，观察离线和恢复。
7. 执行超时：跳过控制命令执行，观察命令超时记录。

场景切换通过设备场景接口更新场景版本，模拟器下一轮获取后应用。页面不是直接向数据库塞入预设报警，而是让模拟器经过实际鉴权、校验、存储和规则流程。

“上报中断”是仿真行为，不是拔掉真实网络后的硬件验收；真实网络异常时模拟器也会捕获HTTP错误并继续运行本地规则。

界面还提供演示与使用说明、统一状态标签、错误提示、弹窗、空数据状态和响应式布局。响应式布局不等于已经完成手机端产品。

（十）统一启动与安全退出

总入口：项目根目录 start.py。

启动顺序：自动选择项目虚拟环境 → 检查.env和前端构建 → 检查端口 → 初始化数据库并执行迁移 → 准备账号、设备、规则 → 启动Uvicorn → 健康检查 → 启动模拟器 → 打开浏览器。

默认访问地址：http://127.0.0.1:8000。首选端口不可用时最多顺序尝试20个端口，并同步更新模拟器地址及浏览器来源白名单。请以启动日志实际显示的地址为准。

退出方式：启动窗口Ctrl+C；登录页“退出系统”；登录后侧边栏“退出系统”；Ctrl+Shift+Q快捷键。

前端退出请求无需登录，但后端校验回环地址、来源和专用请求头。返回202后发送停机信号，总入口通过临时标记识别正常退出并回收模拟器。Windows通过进程组和Job Object管理本次创建的进程树，异常环境有兜底清理。

退出只停止当前项目托管的服务与模拟器，不删除业务表，不结束其他Python程序，也不停止系统中的MySQL服务。浏览器标签页一般会保留退出提示，不保证自动关闭浏览器窗口。

这一整套回收依赖从start.py启动。单独启动后端或使用前端开发服务器时，不属于同一托管进程树，不能把退出按钮理解为关闭电脑上全部相关开发工具。

三、技术栈及每项技术承担的职责

1. Python 3.12
   项目虚拟环境当前版本3.12.14，承担后端、初始化、进程管理、模拟器和测试。系统Python入口会切换到项目.venv，减少IDE与终端依赖不一致。

2. React 19 + TypeScript
   React组织登录、导航、业务页面和可复用组件；TypeScript描述设备、采样、报警、命令和用户数据结构，在编译阶段检查类型使用。

3. Vite 6 + pnpm
   Vite提供开发服务器和生产构建；开发时代理/api及WebSocket到后端；生产构建输出frontend/dist。pnpm及锁文件管理前端依赖。图表和图标依赖拆分为独立构建块。

4. Recharts + Lucide React + CSS
   Recharts绘制实时和历史曲线；Lucide提供统一图标；CSS变量统一颜色、间距、圆角、阴影和响应式断点。当前未使用大型UI组件框架。

5. FastAPI + Uvicorn
   FastAPI实现REST API、依赖注入、数据校验、权限控制、WebSocket和静态文件服务，提供自动生成的OpenAPI/Swagger接口说明。Uvicorn运行ASGI应用。

6. Pydantic + pydantic-settings
   校验字段、枚举、范围和时区；拒绝无效测量值和协议未知字段；从项目根目录.env读取配置，并缓存为进程配置单例。

7. SQLAlchemy 2 + PyMySQL + MySQL 8
   SQLAlchemy维护ORM模型、会话、事务、行锁和连接池；PyMySQL负责MySQL协议连接；MySQL保存业务数据。数据库名默认kitchen_sentinel，使用utf8mb4编码。

8. Alembic
   维护数据库结构迁移，通过alembic upgrade head建立或升级表结构，减少手工建表的不一致。

9. asyncio + WebSocket + 线程池
   异步维护任务调度、实时连接收发和定时推送；同步数据库查询通过asyncio.to_thread在线程执行。普通同步路由由FastAPI在线程池执行。

10. HTTPX
    模拟器通过HTTP连接后端；可选模型摘要通过HTTP连接兼容/chat/completions协议的模型服务。

11. Python标准库
    hashlib/hmac/secrets处理密码与令牌；subprocess/signal管理进程；csv处理导出；datetime统一时间；pathlib计算绝对路径；logging记录运行问题；Windows ctypes封装Job Object。

12. Pytest + Ruff + TypeScript编译检查
    Pytest验证规则及端口选择；Ruff检查Python代码；tsc执行前端类型检查；Vite验证生产构建。

当前后端已安装依赖版本参考：FastAPI 0.141.1、Uvicorn 0.54.0、SQLAlchemy 2.0.54、PyMySQL 1.2.3、Alembic 1.20.0、Pydantic 2.13.5、pydantic-settings 2.15.0、HTTPX 0.28.1。版本信息来自当前虚拟环境，其他电脑重新安装时应以依赖约束和实际环境为准。

四、软件架构与模块划分

总体结构：
电脑浏览器（React页面）
  ├─ REST接口：登录、查询、确认、配置、命令、导出
  └─ WebSocket：实时快照
             ↓
FastAPI应用（接口、权限、监测服务、规则函数）
             ↓
SQLAlchemy / PyMySQL
             ↓
MySQL数据库

独立设备模拟器通过设备HTTP接口与FastAPI通信，在自身进程内完成采样、规则计算、模拟保护和执行回执。

目录职责：
frontend/src/pages：七个业务页面。
frontend/src/components.tsx：标签、弹窗、图表、空状态、提示组件。
frontend/src/api.ts：统一浏览器请求、Cookie与CSRF处理、退出接口。
frontend/src/useMonitor.ts：WebSocket订阅、重连、REST兜底、实时样本窗口。
backend/api：账号接口、平台接口、设备接口和权限依赖。
backend/services/monitoring.py：遥测入库、报警同步、命令创建、维护、快照与审计编排。
backend/domain/rules.py：无网络、无数据库的纯规则计算函数。
backend/core：配置、数据库与密码/令牌工具。
backend/models.py：数据库实体。
backend/schemas.py：请求数据契约。
backend/main.py：应用生命周期、中间件、WebSocket与静态文件入口。
simulator/main.py：独立模拟边缘控制器。
scripts：初始化、运行时切换、端口选择与进程管理。
migrations：数据库迁移。
tests：自动化测试。
start.py：全系统总入口。

这是模块化单体架构，便于当前快速集成与维护；尚未拆分成微服务，也没有引入消息队列、Redis、Kubernetes或MQTT。

五、核心实现链路

（一）遥测接入与数据一致性

1. 模拟器启动时生成boot_id，每次采样增加sequence。
2. 发送包含gas、smoke、temperature、flame、valid、local_alarm和actuators的JSON。
3. 后端按设备Bearer令牌鉴权，再由Pydantic校验。
4. 锁定设备当前状态，按device_id + boot_id + sequence判断是否重复。
5. 重复包返回原样本编号；数据库唯一约束提供第二层保障。
6. 新包写入telemetry，随后更新设备状态和复核报警。
7. 超过约30秒的迟到采样或早于设备当前最新时间的采样仍保留历史，但不倒退最新状态、不刷新在线时间。
8. 正常事务提交；异常时回滚。

设备采样频率目标约1秒一次，网络请求超时等因素可能延长周期。当前没有遥测批量上报API，也没有持久化离线样本队列；模拟器本地状态只保留最后样本及执行记录，不能宣称断网期间的全部数据会自动补传。

（二）规则计算与抗干扰

规则采用“阈值 + 持续时间 + 回差 + 恢复时间”的状态机。

以默认燃气规则为例：
数值达到40后开始计时；持续满足3秒后触发；触发后使用回差，将保持条件降到35；低于保持条件后需要持续5秒才恢复。这样可以抑制短时尖峰，并减少临界值附近的反复触发和恢复。

火灾规则综合烟雾、温度和火焰：烟雾或温度超限按持续时间判断；有效采样中的火焰信号可以立即触发。无效或缺失数据触发传感器故障；已有危险报警不会因为采样失效被直接清除。

evaluate(sample, rules, previous, now)是纯函数。模拟器与后端复用同一份实现，分别进行本地判定和服务端复核。它是确定性规则状态机，不是机器学习识别模型。

每次规则计算只处理固定三类状态，计算量约为O(1)，无需扫描全部历史采样。实时图表通过最近90条窗口控制浏览器数据规模。

（三）控制命令闭环

操作员选择动作 → 平台生成幂等键 → 后端创建commands记录 → 模拟器拉取有效命令 → 标记dispatched → 模拟器执行并原子保存本地状态 → 发送回执 → 服务端写入结果和审计 → 页面更新。

没有回执时，维护任务将过期命令标记timeout，不把“已发送”当作“已执行”。这是可以在中期检查重点展示的工程细节。

（四）事件摘要与可选模型分析

本地规则摘要无需外部服务，从事件期间最多120条最近采样提取样本数、燃气峰值、温度峰值，结合事件原因生成说明并保存。

外部模型调用需在.env填写MODEL_BASE_URL、MODEL_API_KEY和MODEL_NAME。页面展示配置状态，不向浏览器返回密钥。配置不完整时提示未配置，调用异常时返回可读错误，本地监测不依赖模型运行。

模型只能辅助解释证据，不能直接改变报警状态或发送执行命令。当前已实现调用入口和适配逻辑，不代表云端模型服务已经部署或完成联调。

六、数据库设计

业务表共8张，另有Alembic迁移版本表，因此完整初始化后的数据库通常共9张表。

1. users：用户名、密码摘要、角色、有效状态。
2. auth_sessions：会话令牌摘要、关联用户、CSRF令牌、到期时间。
3. devices：设备身份、位置、令牌摘要、最后在线时间、最近采样、规则状态、执行机构状态和场景版本。
4. telemetry：设备编号、启动编号、序号、采样时间、接收时间、燃气、烟雾、温度、火焰、有效性和本地报警。
5. alarms：类型、严重程度、生命周期时间、确认人、时间线、证据与分析。
6. commands：动作、状态、发起人、幂等键、创建时间、到期时间、完成时间和结果。
7. rule_configs：规则JSON、版本号、更新时间。
8. audit_logs：执行者、操作类型、关联对象、详情、时间。
9. alembic_version：数据库迁移版本。

主要约束：用户名唯一；遥测(device_id, boot_id, sequence)唯一；命令idempotency_key唯一；设备与采样、报警、命令之间设置外键；遥测设备与时间、报警设备与状态等设置索引。

时间统一以UTC写入MySQL DateTime，API序列化补充Z，浏览器按本地时区显示。环境配置只保存数据库连接参数，不是数据库文件；DataGrip通过MySQL连接查看kitchen_sentinel数据库。

八、安全、健壮性与工程性

1. 模块职责分离：页面、HTTP接口、业务编排、纯规则、模型与配置分开。
2. 后端权限检查：不仅依靠前端隐藏按钮。
3. Cookie与CSRF：会话Cookie设置HttpOnly和SameSite=Strict，写业务请求校验CSRF。Secure选项可配置，本地HTTP默认不等于已启用HTTPS。
4. 来源白名单：登录、WebSocket及退出路径检查来源；CORS限制允许的浏览器来源。
5. 密钥隔离：.env、.runtime、虚拟环境和依赖缓存加入Git忽略规则。
6. 数据校验：有效采样必须提供测量值，拒绝NaN/Infinity、越界值、未知字段、无时区时间和明显未来时间。
7. 事务与锁：业务写入异常回滚，设备和命令状态变更使用行锁，规则版本防止覆盖。
8. 错误响应：数据库异常提供503及可读提示；其他未处理异常有统一500响应和日志。
9. 请求追踪：HTTP请求生成编号，正常响应附加X-Request-ID及部分安全响应头，API禁止缓存。
10. 状态持久化：模拟器先写临时JSON再替换，减少半截文件；损坏状态文件尝试备份后恢复默认状态。
11. 启动检查：固定根目录路径、解释器切换、端口检测、健康检查和初始化超时。
12. 退出回收：正常中断有宽限时间，不能退出时回收本次进程树，避免遗留监听端口。
13. 中文注释：关键模块说明业务用途、流程和异常边界，方便介绍与维护。

这些做法体现工程化原型建设，但不能把项目直接表述为已经通过企业级安全和高可用验收。

九、异步方式、数据处理能力与当前上限

当前采用“异步网络任务 + 同步ORM + 线程池”的混合方式：
1. WebSocket收发使用async/await。
2. asyncio.create_task启动后台维护循环。
3. asyncio.to_thread执行维护及WebSocket数据库快照，避免把同步数据库I/O直接放入事件循环。
4. 普通同步FastAPI路由通过框架线程池执行。

尚未使用AsyncSession或异步MySQL驱动，所以不能宣称数据库层已经全部异步化；模拟器和外部模型HTTP调用也仍采用同步客户端。

连接池基准容量10、额外允许20，单个后端进程理论连接上限30。连接按需创建，不表示启动时就创建10条连接。等待连接超时10秒，连接建立超时5秒；开启预检查，空闲连接复用采用LIFO，连接回收周期1800秒。

维护循环每轮完成后约等待2秒；每轮最多处理1000条过期会话、1000个设备和1000条超时命令。这些限制控制事务和内存规模，并不表示已经验证1000设备并发。设备维护当前也没有完整分片游标机制，大规模节点需要进一步设计。

性能优化已体现在：固定窗口图表、接口数据上限、数据库联合索引、连接复用、纯规则状态计算、命令与遥测幂等处理、后台批量维护和线程池隔离。

当前没有QPS/TPS、端到端延迟、长期稳定性或千设备压测结果。连接池配置与查询上限是工程边界，不能作为“已达到某吞吐量”的证据。

十三、常见问题与回答

问：电脑端是桌面软件吗？
答：当前是本地浏览器Web系统，React负责界面，FastAPI提供接口和构建后网页，MySQL保存数据。这样可以统一部署并为后续其他客户端复用接口。

问：数据是不是页面写死的？
答：数据由独立模拟器生成，通过鉴权和数据校验写入MySQL，再通过API和WebSocket展示。数据内容是仿真值，但传输、存储和业务流程真实运行。

问：硬件是否完成？
答：目前未完成真实硬件接入与标定。本阶段使用设备模拟器验证软件流程，真实硬件采购、检验和接入情况应按照实际进度另行说明。

问：为什么有本地规则还要后端判断？
答：模拟器承担设备侧实时判断和模拟保护，后端复核用于形成统一事件、记录证据和支持远程查询；当前两端复用同一套纯规则函数，减少判断口径不一致。

问：为什么不能只看一次超过阈值？
答：瞬时干扰可能产生尖峰，因此持续时间用于确认异常；回差及恢复时间用于减少阈值附近的状态抖动。

问：点击关阀是否等于阀门已经关闭？
答：不等于。点击只是创建命令，必须收到设备回执才标记执行结果。当前回执由模拟器产生，真实项目还需物理阀位反馈。

问：数据库怎样避免重复？
答：遥测采用设备编号、启动编号和序号组成唯一键，命令采用幂等键；关键操作配合设备或命令行锁及事务处理。

问：使用了什么AI算法？
答：实时报警核心是可解释的规则状态机，不是AI识别。模型接口仅用于可选事件摘要，未配置时本地规则摘要可以正常使用，模型不参与控制执行。

问：现在是否已经全异步、高并发？
答：目前是异步任务和同步数据库线程池的混合实现，已配置连接池、索引和数据上限，但尚未经过大规模压测，不能给出未经验证的吞吐承诺。

问：现在能支持很多设备吗？
答：数据库和接口按device_id区分节点，设备页面可以展示列表，但当前默认只有一个模拟节点，总览和人工控制以第一个设备为主。完整多设备体验需要继续扩展和验证。

问：云、软件、硬件一体化完成了吗？
答：当前完成本地软件与模拟边缘设备的闭环，并预留设备协议和客户端接口。真实硬件、手机端及云运行属于后续集成任务。

问：如何证明可维护性？
答：可以展示目录职责、纯规则函数、Pydantic契约、ORM模型、迁移脚本、统一API模块、中文注释及基础测试，说明增加设备协议适配或新页面时应修改哪一层。
