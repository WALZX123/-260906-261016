# STM32F103 实物采集与联动固件

当前固件：`stm32f103-hwtest/6.0`，状态 ABI6、命令 ABI2。整理及复验日期：2026-10-16；源码日期按实习日志工作项标注，实际下载时间单独记录。

**当前 Keil 入口：`CubeMX/MDK-ARM/KitchenSentinel_F103.uvprojx`。CubeMX 入口：`CubeMX/KitchenSentinel_F103.ioc`。业务源码：`CubeMX/Core/Src`，接口：`CubeMX/Core/Inc`。** 原来的 Projects/MDK-ARM 仅保留历史记录，不再作为本版入口。

## 工程组织

参考工作区 myclassdemo001.zip 的 CubeMX 根目录组织方式，将实际源码、Drivers、DeviceSupport、MDK-ARM、Output 和 tools 集中在 CubeMX 下。参考案例为 F103ZE，本项目为 F103C8；未搬用其引脚、存储容量或 RT-Thread 程序。现有应用采用 C、CMSIS、STM32 HAL、ARMCC5 和主循环状态机。

Keil 工程内有“基础配置 CubeMX”分组，可以打开 IOC、引脚表及说明；源码导航使用本地头文件和 Browse Information。更换电脑后先 Rebuild All。原厂 SDK、器件包和编译器头文件保留原版权，闭源 ARM 标准库的实现不在交付范围内。

## 正常运行与保护

上电先关阀待机，OLED 与通信立即初始化，不自动采样。管理员或操作员在“设备启用”开启，建立八点基线后无险情才开阀。险情时关阀锁定，恢复信号和人工确认都不自动开阀；现场核查后另行执行“恢复运行并开阀”。

| 模块 | 使用方式 |
| --- | --- |
| ADC1 | PA0 烟雾 AO、PA1 NTC、PA5 燃气电位器、PA7 火焰 AO，动态逐通道采集与独立八点均值 |
| 数字输入 | PB5 烟雾 DO 诊断，PB1 火焰 DO 低有效；火焰 AO/DO 合并判断 |
| 保护输出 | PB0 蜂鸣、PB12 低压继电器、PA8 风扇正向；PB13 反向保持低 |
| 舵机模型 | PA6 TIM3_CH1，50Hz，500μs 关、1500μs 开，无机械阀位反馈 |
| OLED | PA2/PA3 软件 I²C，14×14 中文和6×12数字，四行核心信息常显，不轮页 |
| Wi-Fi | USART3 PB10→模块RX、PB11←模块TX，PA4复位；MB026在同一2.4GHz热点传遥测、规则、命令、回执与补传 |
| 调试 | USART1 PA9/PA10 115200；SWD下载、读回、诊断及后备通道 |

燃气越限：关阀、低压模型排风、蜂鸣和保护继电器。烟雾、高温、火焰及复合火灾：关阀、蜂鸣、保护继电器，停止普通风扇，升级人工。16项命令包括启停、开关阀、限时消音、自检、四项输出测试、五类限时险情演练和取消演练。真实险情优先中止演练；原始ADC与演练判定分别保存。

烟雾接线 AO→10kΩ→PA0，PA0→20kΩ→GND，共地。燃气/烟雾仅为0～100相对指标，NTC温度为标称估算；用户已确认实际执行器动作正常，但GPIO/PWM报告不能替代机械位置或触点测量。

## OLED 与启动

第一行显示灶安、待机/检查/运行/警情、演练标记与Wi-Fi；第二行燃气和烟雾；第三行温度和火焰；第四行阀门、风扇、蜂鸣、继电器。序号、运行时长、质量及缓存诊断移至PC。初始化和首帧在自检、Flash队列扫描、ADC校准及联网之前执行；未启用时显示待机与横线。整帧绘制后只发送变化页。用户在2026-10-16确认“清楚，排版可以”。该反馈是实物可读性确认，不等于测得冷启动亮屏毫秒数。

## 断网存档

| Flash 分区 | 范围 / 容量 |
| --- | --- |
| 应用 | 0x08000000～0x08009FFF，40KiB，Keil IROM长度0xA000 |
| 采样队列 | 0x0800A000～0x0800FBFF，23页，每页25条，共575条40字节记录 |
| 私有配置与启动身份 | 0x0800FC00～0x0800FFFF，1KiB |

未收到服务器数据库提交确认的采样会进入队列，恢复网络后按原启动身份与序号幂等补传。约500ms网络存档间隔对应数分钟容量；它不是每100ms本地ADC轮次的永久录像，也不提供无限离线保存。满时保留已有待传记录、计数并向平台报告存档缺口。已提交Flash的记录可跨复位保留；突然断电时尚未落盘的即时样本不保证保留。

收到校时后用单调运行时间延续离线时间戳；冷启动尚未校时明确记为时间未知，没有新增RTC。补传不覆盖当前设备状态、不执行旧控制命令；恢复的离线异常仍待人工确认。网页数据中心按采集时间查询和导出全部入库记录。

## Keil 下载

1. 使用当前工程，目标选择 **Download**，按 **F7**。构建后自动调用 `tools/keil_download.py`，执行备份、下载、逐字节读回及运行观察。
2. 看到 `Verified 37844 firmware bytes; no mismatches`、`0 Error(s)`，才表示这版固件下载校验成功。用户已在2026-10-16实际确认该入口成功。
3. **Template**目标只编译。更换位置后先重建；若程序改变，校验字节数可能随之变化，不能长期写死为37844。
4. 无线专用运行不占用探针；SWD后备或调试会话必须正常退出后再下载。探针跨进程独占锁会拒绝并发使用。

原先 Keil 原生擦写报错与 ATK 2.1.2 CMSIS-DAP 传输兼容有关。本版在 Keil 内调用已验证的 pyOCD 通道：500kHz、单包、关闭延后传输、复位并暂停后编程；另修正AfterMake返回码判断（退出0成功，>=1失败）。不把原生驱动擦写问题描述为已经修复。Utilities外部工具已配置；本次实际确认的演示入口是Download目标F7。

完整项目自带.venv。独立包在同层项目根建立.venv并安装pyOCD0.45.1，保留firmware/stm32f103_hardware_test/CubeMX嵌套结构。工具不依赖平台业务代码。完整Flash备份包含私有信息，仅存本机.runtime，不随工程包分发。
